# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-11-03 | GitHub for the repo, private until submission | Rules need an install link, a video and a description, not a repo. Claude Code works with GitHub directly. |
| D2 | 2026-11-03 | npm scripts, no Makefile | Windows machine, no make. |
| D3 | 2026-11-03 | Assets enter the Teamwork Graph as `atlassian:document` asset cards, Forge storage is the source of truth | The graph has no device, asset or vulnerability object type. |
| D4 | 2026-11-03 | Raw export stays in `data/raw/` (gitignored). Only the generated, remapped dataset is committed. | Leak check enforces it. |
| D5 | 2026-11-03 | Fictional company Tervaniemi Works, agent Pentti | Names live in `config/names.yml`. |
| D6 | 2026-11-03 | Seeded content dates live in the app, scores never read Atlassian created or updated dates | Jira REST refuses `created` on create (limits.md g). |
| D7 | 2026-11-03 | Asset card to Confluence page links are kept in app storage and written into the card text, not as graph associations | No Confluence page association type exists (limits.md h). |
| D8 | 2026-11-03 | App registered in Developer Space `pentti`, not as a personal app | The space refuses personal apps. |
| D9 | 2026-11-03 | Node 24.22.2 pinned in `.node-version` via fnm | Forge CLI 15 refuses Node 24.14. |
| D10 | 2026-11-03 | OT-like means an OT device type outside Purdue 3 and up, or any Purdue level 0 to 2.5. Scope is OT-like plus every host with findings plus 100 random IT neighbours. | Gives 309 OT-like rows (spec says 307) and 522 assets, inside 450 to 550. |
| D11 | 2026-11-03 | Model, firmware and manufacturer come from findings. A host with several modules takes the most frequent tuple. Assets without findings have model null. | The inventory export has no model or firmware fields. |
| D12 | 2026-11-03 | Findings join by IP. When one IP carries several host ids, they map to the inventory rows on that IP in record order. A duplicate IP keeps the address of its first holder, also across lines. | Keeps the export's ambiguities instead of repairing them. |
| D13 | 2026-11-03 | Nicknames are unique within a plant and may repeat across plants. Pool of 60. | 25 percent of about 300 OT assets needs more than 60 names. Cross-plant repeats are realistic and exercise the ambiguous-match path. |
| D14 | 2026-11-03 | Asset and finding ids are hashes of seed and record position, never of original values. | A salted hash of an IP could be brute forced. Record order is preserved in the export, so position is stable. |
| D15 | 2026-11-03 | Old Faithful is `birch-l2-cp-04`, not `birch-l3-cp-04`. Pinned in `config/names.yml`: the CPU 315 rack that also holds a CP 343-1, 33 open findings, max score 9.3. | Birch line 3 holds one printer in the data. Moving the asset would invent topology. |
| D16 | 2026-11-03 | A person touches an asset when they report or are assigned an issue that mentions it, or author a page that mentions it. Owner = an active person who touched it in 24 months and does not leave within 180 days. | One rule for the generator checks and for the S3 knowledge score. |
| D17 | 2026-11-03 | `mentions[]` holds `{assetId, kind}` with kind exact, nick, old, model, model_line, model_plant. Assets gain `modules`, `ipHistory`, `formerNames`. | Matcher recall is measured separately on exact and old mentions (5.5). The matcher may use history, as section 6 allows. |
| D18 | 2026-11-03 | Narrative sources are `narrative/pages/*.md` and `narrative/issues/*.yml` with `[[ref|form]]` markup, rendered by the generator. 61 pages: the 60 in 5.4 plus the NIS2 page, class `reference`. | Text stays readable and the ground truth cannot drift from it. |
| D19 | 2026-11-03 | People who left carry `leftDaysAgo`. The integrator is a person entry. | Owner rules need to tell gone from leaving. |
| D20 | 2026-11-03 | Matcher confidences: hostname and current IP 1.0, old IP or former name 0.9, old IP that another machine holds now 0.7 (the holder 0.3), nickname 0.7, model+line 0.5, shared IP 0.4 each, ambiguous nickname and model+plant 0.3. A nickname outside the plants the text is about is ambiguous. | Never guess between two machines. A reused address is evidence for the machine that had it (hero 4). |
| D21 | 2026-11-03 | The closing list ranks assets, not single gaps. Each asset brings all its closable gaps: name 0.5 h, owner 0.5 h, new doc 2 h (doc and fresh), refresh 1 h, confirm 0.5 h. History and firmware have no price and are not closable from a desk. | "These ten assets, N hours" is what a plant manager can assign. |
| D22 | 2026-11-03 | `config/scoring.yml` is copied to `data/generated/scoring.json` by the generator. The app and the tests read only the JSON. | One source of weights, bundled with the app, covered by the determinism test. |
| D23 | 2026-11-03 | Scores use real data only. Top 10 for the whole factory: 18.5 hours, 2.3 percent of the danger, because 522 assets carry a lot of danger. The video line in section 15 uses whatever the app returns, per plant if that reads better. | Numbers come from the action output. |
| D24 | 2026-11-04 | The generated dataset stays in the app bundle. KVS holds only what changes: the seed config, the seeded map (unit id to remote id), the install date, later confirmations. "Load the factory" seeds Confluence and Jira and sets the install date. | The dataset is read only and 1.5 MB. Copying it to KVS would add reads on every request and a second copy that can drift. Section 8 queries run in memory over the bundled index. |
| D25 | 2026-11-04 | All pages go into one Confluence space the admin picks, under a root page `Tervaniemi Works (fictional)` with one section page per source space (Operations, Network, Safety, Projects). Jira issue types map to what the project offers (exact name, then a fallback list, then Task). Done issues are moved to a done-category status. | The admin picks one space and one project (section 10). The original space and type stay in the dataset. |
| D26 | 2026-11-04 | Idempotency: every seeded object carries `pentti-demo` and `pentti-demo-<id>` (a dash, Confluence refuses colons in labels). KVS keeps the map, and the first step of every load or reset rebuilds it from a label search (JQL and CQL). Reset deletes only mapped or labelled objects, leaves first. | A lost KVS write cannot cause duplicates or orphans. |
| D27 | 2026-11-04 | Admin resolvers check, on every call, that the user behind `context.accountId` holds the Jira ADMINISTER global permission (asked as that user). | The admin page is only shown to admins, but resolvers are callable from any frame of the app. |
| D28 | 2026-11-04 | The manifest declares `compatibility`: Jira required, Confluence optional. One installation spans both. | Only then can the Jira app call Confluence (limits.md, seeder notes). Judges install into Jira first, then connect Confluence. |
| D29 | 2026-11-04 | Gap tasks carry `pentti-demo` and `pentti-gap-<assetId>` (dash, as D26). create-gap-tasks searches by that label before it creates, and creates as the user, after a CREATE_ISSUES check for that user in the loaded project. Reset removes gap tasks too. | Idempotent, the user's own permissions apply, and the demo cleans up after itself. |
| D30 | 2026-11-04 | The agent prompt lives in `prompts/pentti.md`. `tools/sync_prompt.py` copies its fenced block into the manifest on deploy, `npm run check` fails when they differ. The spec prompt is kept word for word, a "How to work" part maps questions to actions. | One readable source, no drift. |
| D31 | 2026-11-04 | explain-asset always lists spare parts and upstream or downstream machines under not known. With linked pages the spare parts line says to check them. | No structured source holds either. The honest answer is that the app does not know. |
| D32 | 2026-11-04 | Actions get an asset id, never a free text name. An unknown id returns an error plus the search candidates, never a guess. | Inputs come from a language model. |
| D33 | 2026-11-04 | Traffic lights come from `bands` in `config/scoring.yml`: risk red at 80, amber at 60; danger red at 50, amber at 25; knowledge green at 60, amber at 30. One tested function (`src/score/bands.ts`) decides every colour, the server sends the colours, the UI only draws them. | Picked from the real distribution: 69, 188 and 265 assets on risk, 100, 207 and 215 on danger, 338, 39 and 145 on knowledge. Colours are always paired with words, never colour alone. |
| D34 | 2026-11-04 | The gap map's red corner is knowledge below amber (30) and risk at least amber (60). The counter line "Critical and nobody knows anything" counts Critical assets with no name and not one counted page or ticket, from the app's own matcher. | With risk at 80 the corner held 2 assets. Most nameless Critical machines have no findings and sit at risk 60. The S2 check used generator ground truth, the UI uses what the app can see. |
| D35 | 2026-11-04 | Bus factor: a person is the only name on a machine when they are the one person still here who touched it through a counted page or ticket in the owner window (24 months). People who left are never the only name. | Matches the owner rule (D16) and the video line about Pentti. |
| D36 | 2026-11-04 | "I checked this" stores `confirm:<assetId>` with the account id and time. Any signed-in user may confirm. Reset clears confirmations. The gap map and the card read them through the knowledge score. | The confirm dimension needs a human, not a role. |
| D37 | 2026-11-04 | Every asset has a deep link, `<site>/jira/apps/<appId>/<envId>/asset/<assetId>`, built from `getAppContext()`. Actions return it as `url`, the agent writes machine names as markdown links to it, graph cards use it as their url, the Pentti page opens the card from it. | One address per machine, never built by the model. |
| D38 | 2026-11-04 | One `atlassian:document` card per asset (522), batched by 100, request property `source: pentti`. Text carries names, address, model, scores with light words, people, page titles with links, ticket keys, not known. Seeded Jira issue keys are `issueIdOrKeys` associations. Sync on connect, after Load and Reset, from the admin page, one card after "I checked this". Disconnect deletes by the `source` property. | Mirror fidelity without a scheduler. Rovo finds machines by any of their names. |
| D39 | 2026-11-04 | `rovo:mcp` exposes only find-asset, explain-asset and gap-report. Writes stay inside Rovo, where the user confirms them. | MCP clients run outside Atlassian's confirmation step. Read-only tools cannot hurt anything. |
| D40 | 2026-11-04 | No Marketplace listing. Judges install from the distribution link. | Forge apps compatible with more than one Atlassian app can only be listed as paid apps, `rovo:mcp` is Preview, and a listing review does not fit the deadline. Decided by Juha. |
| D41 | 2026-11-04 | `tools/token_hashes.txt` (unsalted SHA-256 of tokens from the raw export, in every commit since S0) stays, history included. The repo may go public with it. | The raw export was already anonymized before it reached this project, so the hashes reveal anonymized identifiers only. Decided by Juha after the brute-force risk was raised. |
| D42 | 2026-11-04 | S9 closes without the fresh-site test. The "Done when" (someone else installs on a clean site, first answer under 10 minutes) is not met. | No second site and no tester available. Decided by Juha, to keep time for the video. If a site appears later, `forge site provision` from the CLI made the first demo site and could make another. |
| D43 | 2026-11-05 | Own data proof of concept beside the demo: CSV asset list, one Jira project and one Confluence space. Bundled data stays the default and unchanged, `tests/bundled-baseline.test.ts` freezes its outputs from the code at tag `rollback-before-own-data`. | Lets someone try real data without risking the demo. Asked for by Juha after reading the rules. |
| D44 | 2026-11-05 | Own data is read only: GET requests as the admin who imports, tasks off, own: storage keys that the seeder and Reset never read, its own matcher class. | Reset deletes what its map holds. Real pages must never get near that map. |
| D45 | 2026-11-05 | While a site runs on own data only Jira admins get answers, on every path, and fails closed. Nothing goes into the Teamwork Graph. | Titles were read with one admin's permissions, and graph cards are visible to everyone on the site. |
| D46 | 2026-11-05 | Page and ticket text is not stored, only titles, dates and what matched. Links are worked out at import. Answers come from the import, not live. | Least data kept, fast reads, and a clear date to state in the answer. |
| D47 | 2026-11-05 | No people in own data. Owner and who knows are not known, highest knowledge score 80. Hostnames that could be a word stay a maybe. A page naming more than 25 machines is a list and counts as a maybe. | Better an honest gap than a false owner or a whole fleet documented by one inventory page. |
